AI Draft 结构化渲染

把案件详情页里那块装着原始 JSON 的 textarea，改造成一个可读、可核对、可编辑的调查草稿面板。 这一屏承载演示的最后一个高潮：分析师当场修正 AI 的措辞并署名。

预计工时
2 小时 30 分
涉及文件
2 个（纯前端）
后端改动
可选，10 行
验收
7 步走查

现状与目标

当前 AI 面板是两个按钮加一个 <textarea>，里面塞着整段 JSON （case.html:93），并且被 grid-2 挤成半宽 （case.html:85）。评委看到的是一坨大括号。

后端已经返回结构化数据了，四个字段齐备。前端只是没有把它渲染出来——所以这是一个纯展示层任务， 不需要动规则引擎、不需要动数据库。 

POST /api/cases/{id}/ai-draft   → 生成草稿
PUT  /api/ai-drafts/{id}        → 提交分析师最终版

rawOutput 的结构（已实现，可直接依赖）：
{
  "narrative": "3-4 句资金流向叙述",
  "confirmedObservations": [
    { "statement": "...", "evidenceIds": ["R1-ALERT-1", "TXN-002713"] }
  ],
  "unexplainedQuestions": [ "..." ],
  "suggestedNextChecks":  [ "..." ]
}

已决事项 · 不要重新讨论

分析师只能编辑 narrative，其余三段只读

narrative → 可编辑　｜　observations / questions / next checks → 只读

narrative 是分析师签字的话，应该用她的措辞。confirmed observations 带证据链接、由机器推导， 让她自由改写会破坏可追溯性——她不认可就重新生成，或在处置理由里写明。

这条也正好对准演示动作：要改的就是 This may constitute layering. 那一句。

analystFinalText 存完整 JSON，不是那一句

读取：analystFinalText ?? rawOutput → 解析 → 渲染

审计留痕的原则是签字对象必须自洽完整。只存片段的话，三个月后回看不知道她当时接受的全文是什么。 提交时取当前 JSON、替换 narrative、整个 PUT 回去。

模型编造的证据编号标成 unverified，不做成链接

命中索引 → 可点击 chip　｜　未命中 → 灰色 unverified 标记

前端用 timeline 的 txnRef 和 alert 的 id 建索引，命中才可点。 五行代码换来一句很有分量的话：如果模型引用了一条不存在的交易，界面会标成未验证，而不是假装它存在。

四段要有不同的视觉权重：narrative 用正文字号，observations 带项目符号加证据 chip， questions 用问号前缀并弱化，next checks 用箭头前缀。 不要做成四个长得一样的方框——层次感是这一屏说服力的来源。

兜底 · 必做

结构化渲染不能成为新的翻车点

目前走的是模板路径，输出稳定。但演示当天如果 Ollama 起来了，模型可能返回解析不了的东西。

  • 解析失败：退回当前的 <pre> 原文显示，顶部加一行提示 Structured view unavailable — showing raw model output
  • 字段缺失：缺哪段就不渲染哪段，不要抛异常，不要渲染空标题
  • 数组为空：整段隐藏，而不是显示一个空列表

验收走查

跑之前先起服务：./run.sh（它会固定 JDK 17 并带上 demo profile）， 然后打开 CASE-2026-0001（ACME Trading Ltd，83 分）。

  • 点 Generate draft → 四段清晰可辨，视觉层次分明，页面上看不到大括号
  • 点任一 TXN-002716 chip → 时间线对应行滚动到视野中央并闪一下
  • 点 Edit → 把 This may constitute layering. 改成 This shows rapid dispersal of funds and requires further investigation. Beat 5
  • 点 Accept → 页面不刷新，narrative 上方出现 Edited and accepted by sarah.chen Beat 5
  • 滚到 Audit trail → AI_DRAFT_GENERATED 和 AI_DRAFT_EDITED_AND_ACCEPTED 两条都在
  • 展开 +30 R1 → 看到 强度 0.854 × 权重 35 = 30 分，不是 JSON Beat 1
  • 手动把 rawOutput 改坏 → 退回原文显示并给出提示，不白屏、不报错

第 3 到第 5 步连起来就是演示里 Beat 5 的完整动作。排练时按这个顺序走。

不要做的事

  • 不要改后端评分逻辑。分数、告警、证据快照都已定稿并有测试覆盖，改了讲稿数字就得重来。
  • 不要引入前端框架或构建步骤。现在是纯 HTML 加原生 JS，改完刷新即见。周四之前不值得为此付出配置成本。
  • 不要让 AI 面板出现任何能改分数、改状态、改 CRR 的控件。这是整个项目的立论，界面上不能有反例。
  • 不要动 rawOutput。它是模型原始输出，必须保持不可变；分析师的修改只进 analystFinalText。
